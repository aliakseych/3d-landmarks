# Contributing

Contributions are welcome: new landmarks, better models, viewer fixes, and pipeline improvements. By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Licensing of contributions

- Code is contributed under the [MIT License](LICENSE).
- Models, renders and metadata are contributed under [CC BY 4.0](LICENSES/CC-BY-4.0.txt).
- Only submit photos and models you made yourself, or that carry a compatible licence (state its source and licence in the PR).

## Setup

- [Git LFS](https://git-lfs.com): `git lfs install` before cloning. `.gitattributes` routes `*.glb *.obj *.fbx *.png *.jpg …` to LFS automatically. Check with `git lfs ls-files` before you push.
- Viewer: Node 24+ and pnpm (the version is pinned in `viewer/package.json` → `packageManager`).
- Pipeline: macOS on Apple Silicon (Object Capture), Blender ≥ 4.2, exiftool, python3 with numpy, PIL, trimesh and scipy. Details are in [`.omp/skills/photogrammetry-model/SKILL.md`](.omp/skills/photogrammetry-model/SKILL.md).

## Adding a landmark

1. **Pick a slug.** Use lowercase kebab-case English: `kukeldash-madrasa`, `tv-tower`. It names every folder and file.
2. **Scaffold:** `scripts/new-landmark.sh <slug>`. This creates `temp-captures/<slug>/`, `work/<slug>/` and `models/<slug>/README.md`.
3. **Capture.** Put the original photos in `temp-captures/<slug>/`, following the capture checklist in the photogrammetry skill: 30–60+ shots all around, GPS on, overcast light. This folder is gitignored. **Never commit raw captures**: they are large and embed GPS and device EXIF.
4. **Build the textured master** with [`photogrammetry-model`](.omp/skills/photogrammetry-model/SKILL.md). Deliverables are `models/<slug>/<slug>.glb` and `<slug>.json`.
5. **Build the Yandex model** with [`yandex-maps-3d-model`](.omp/skills/yandex-maps-3d-model/SKILL.md). Deliverables are `models/<slug>/yandex/<slug>_yandex.{glb,obj,fbx}` and `preview.jpg`. `validate.py` must pass and `gltf-validator` must report 0 errors.
6. **Document it.** Fill in `models/<slug>/README.md`: files, location, axes, dimensions, coverage and limitations.
7. **Add it to the viewer** in `viewer/src/data/`: description, facts, and at most 2 photos with author, licence and source URL. Strip EXIF from any of your own photos: `exiftool -all= -overwrite_original <file>`.
8. **Open a PR.** CI builds the viewer on every PR; merging to `main` deploys it to GitHub Pages.

## What goes in a PR

Commit:

- `models/<slug>/**`
- `viewer/**` sources and photos
- pipeline changes under `.omp/skills/**`
- docs

Don't commit:

- `temp-*`
- `work/`
- `viewer/public/models/` (generated by `pnpm dev`/`build`)
- `viewer/dist/`
- `node_modules/`
- the compiled `objcap` binary

Keep commits focused (models, viewer and docs separately) and write messages in Conventional Commit style: `feat(models): add kukeldash-madrasa`.
